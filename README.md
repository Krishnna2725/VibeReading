# VibeReading

VibeReading 是一个面向 Coding Agent 的阅读陪伴页面生成 Skill。它将一本书的目录、气质与阅读节奏转译为一个可双击打开的 16:9 桌面网页空间。

它不是电子书阅读器、剧情讲解器或解谜游戏。当前版本的目标是用画面、声音、天气、文字和低干扰交互，帮助读者进入并维持阅读状态。

## 当前版本

当前开发版本为 VibeReading V2，权威生成契约是 [`SKILL.md`](SKILL.md)。

V2 提供五个平等模板：

| 模板 | 核心动作 | 主要形态 |
| --- | --- | --- |
| `window` | 观看与等待 | 窗边阅读空间，可使用一张基础图和最多三张阶段变体 |
| `vinyl` | 放下唱针 | 唱片机、唱片与封套组成的声音空间 |
| `instrument` | 调频与接收 | 由 DOM、CSS、SVG 与 p5 构成的阅读接收器 |
| `route` | 移动与停留 | 路线图、节点和旅途节奏组成的阅读路径 |
| `oracle` | 抽取与凝视 | 牌桌、牌组与象征系统组成的阅读仪式 |

每个生成页面必须具备：

- 每次刷新都会出现、由用户点击推进的读前引导；
- 一首与全书气质匹配的纯音乐 BGM，以及必要的环境音回退；
- 根据真实目录或章节顺序划分的 3 至 6 个无剧透阅读阶段；
- 与当前阶段匹配、可调节的天气或空间氛围运动；
- 模板专属的陪伴控制方式，而不是通用悬浮面板；
- 阅读计时器和 25 分钟番茄钟；
- 适配 16:9 横屏并支持 `file://` 双击运行的 HTML、CSS 与 JavaScript 交付物。

共享 runtime 负责稳定的状态、声音、天气和计时能力；模板文档负责主体对象、构图、材质、交互语言与陪伴组件。Agent 应根据书籍重新完成艺术方向，而不是复刻既有输出。

## 目录

```text
SKILL.md                 主流程与最高优先级契约
references/              模板、视觉、引导、天气、音频与技术规范
runtime/                 页面共享运行时
scripts/                 脚手架、BGM 生成与确定性校验工具
assets/                  可复用的本地音频资源
output/                  本地生成结果，不进入 Git
```

使用时从 `SKILL.md` 开始，只按当前步骤加载所需参考文档，不要一次性读取整个 `references/`。

## 仓库维护纪律

### 分支

- `main` 是稳定发布线。`v1.0.0` 永久指向第一版基线，不重写、不移动。
- `dev` 是日常开发线。本地开发、阶段性清理和可验证的里程碑都提交到这里。
- 临时任务分支使用明确前缀，例如 `agent/`、`fix/` 或 `experiment/`。任务合并或确认废弃后立即删除，不长期堆积。
- 日常工作默认在 `dev` 上进行。只有准备发布时，才将经过人工确认的 `dev` 里程碑合并到 `main` 并创建新的版本标签。

### 提交

- 一个提交只表达一个完整意图，提交信息说明做了什么，不写模糊的 `update` 或 `misc`。
- 推送前先清理调试文件、废弃方案、重复文档和临时产物。
- 不为了让校验变绿而提交空文件、零字节媒体或伪造 fixture。
- 不直接覆盖他人尚未确认的改动；发现冲突时先确认来源和保留策略。

### 允许进入仓库的内容

- 当前生效的 Skill 契约、模板和必要参考文档；
- 共享 runtime、脚本及其真实有效的确定性测试；
- 页面运行所必需且有明确来源的本地资产；
- 能解释当前架构、使用方式和发布状态的维护文档。

### 不进入仓库的内容

- `output/` 中的书籍生成结果；
- API Key、个人 Token、账户配置和本机代理信息；
- 下载缓存、构建缓存、日志、临时截图和系统元数据文件；
- 从其他 skill 复制来的重复副本，除非它已经被明确吸收并成为本项目维护的一部分；
- 已废弃的规范、无调用方的 fixture、空占位资源和仅用于一次性排查的文件。

### 发布

1. 在 `dev` 完成一个可说明、可运行、可回退的里程碑。
2. 检查差异，确认没有本地输出、密钥、缓存或无效资产。
3. 运行与改动直接相关的确定性检查。
4. 将 `dev` 合并到 `main`，不要直接在 `main` 上试验。
5. 使用语义化版本标签创建 GitHub Release，并写清主要变化与已知限制。

美术质量由人类最终判断；自动校验只负责确认代码、路径、状态与核心交互契约能够运行。
