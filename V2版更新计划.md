# VibeReading V2 Implementation Plan

This document is an archived planning summary. The authoritative generation contract is `SKILL.md`.
If this document conflicts with `SKILL.md`, follow `SKILL.md`.

## Product Definition

VibeReading V2 generates a high-quality 16:9 desktop reading companion space for a book.
Every page begins with a short sound-enabled pre-reading guide, then enters a calm companion space
with a book-specific visual object, weather, sound, TOC-based stages, timer, and pomodoro.

The page is not a plot guide, puzzle game, ebook reader, or productivity dashboard.

Priority order:

1. book-specific identity and atmosphere;
2. main visual or main object;
3. BGM and ambience;
4. weather / atmospheric effects;
5. pre-reading guide;
6. reading stage switching;
7. reading timer and pomodoro;
8. small template-specific interactions.

## Confirmed Decisions

- Five templates are equal: `window`, `vinyl`, `instrument`, `route`, `oracle`.
- The old `symbols` name is deprecated; use `oracle`.
- Every refresh returns to the pre-reading guide.
- The guide is repeated every time and does not use saved completion state.
- Sound is required after the user clicks Start.
- Each book uses exactly one instrumental BGM.
- Browser autoplay rules mean sound begins only after user interaction.
- BGM requests must include `is_instrumental: true`.
- BGM failure must fall back to ambience.
- Reading stages are derived from the real TOC or chapter order.
- Stage count is decided by the agent: minimum 3, maximum 6.
- Stages are spoiler-safe and do not explain plot.
- Only `window` may use one base image plus up to three image-to-image variants.
- Other templates mainly express stage changes through weather, light, sound, text, object state, and motion.

## First-Level Capabilities

Every template must provide:

1. pre-reading guide;
2. weather / atmosphere control;
3. sound control;
4. 3 to 6 TOC-based stage switching;
5. reading timer;
6. 25-minute pomodoro.

These capabilities must be embedded into the template-specific companion control.
Do not use a large generic panel.

## Guide Direction

The guide is a short reading meditation, not a product tutorial.

It should:

- be aimed at readers who have not read the book;
- avoid spoilers;
- avoid unexplained proper nouns;
- use concise poetic copy;
- combine sound, visual focus, weather, typography, and object feedback;
- wait for user clicks instead of auto-playing to completion.

## Template Notes

### Window

Image-led window-side reading space.
The window and outside view must dominate the image. Weather and light carry the stage changes.

### Vinyl

Record-player ritual with one BGM. Stages are expressed through tonearm position, grooves, sleeve notes, or label marks.

### Instrument

CRT Reading Receiver with screen, channel controls, tuning, volume, power/guide, LCD timer, and signal/noise feedback.

### Route

Route or journey object with stations, path segments, current marker, weather, and a travel-like companion control.

### Oracle

Spoiler-safe reading card table. Cards offer reading angles, not fortune telling or puzzle clues.

## Validation Policy

Validation should be deterministic:

- required files exist;
- JSON files parse;
- JS syntax is valid;
- local assets exist;
- runtime contracts are present;
- 16:9 and file:// constraints are satisfied.

Do not ask the generating agent to perform long aesthetic self-review. Human users judge art direction.
