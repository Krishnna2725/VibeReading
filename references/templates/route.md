# 路线与旅途

## 模板标识

当读者需要体验公路、河流、流放、迁徙、旅行、沿途车站、人生阶段、朝圣或一系列地点的变迁时，使用 `route` 模板。

## 概念图作用

`concept-image.png` 通常应作为**路线的载体 (Route Surface)**：铺开的地图、车窗外流动的公路、河流、折叠的纸张、海岸线，或没有可读文字的车站站牌。

为前端生成该图像时：在画面中留出一条强烈的横向或纵向路径，并在沿途留出空旷的“车站”区域。前端将负责在上面添加停靠标记、天气、时间以及旅行日志的 UI。

## 美术指导偏好

路线手书、折叠地图、公路路灯、河流线、旅行笔记本、车站纸张、交通工具内部、稀疏的地平线。

## 世界动词

移动 (move) / 停靠 (stop) / 标记 (mark) / 休息 (rest)

## 推进机制

页面通过停靠站点来推进，而不是普通的章节。

优秀的节奏示例：
```text
空白路线 -> 第一个停靠点 -> 天气/时间变化 -> 休息页
车窗视角 -> 车站标记 -> 绕路选择 -> 旅行日志
```

## 协议映射

- `entry`: 可以是一条公路标线、折叠的地图、车窗、空白站牌，或者一个发光的站点。
- `exploration`: 应该包含选择停靠点、打开车站笔记、切换天气/时间，或标记走过的距离。
- `companion`: 变成路边休息站阅读页 (Roadside Rest Page)、旅行日志 (Travel Log)、车站长椅上的便签，或是夜间车厢里的一盏孤灯。

## 交互物件与控件

使用 2-5 个锚点物件：停靠标记、指南针刻度、车票、河流拐弯、里程碑、车窗反光、地图折痕、车站灯。

舞台控制项可以是车站、里程刻度、路线串珠、折叠标签或时间标记。

## 模板运行契约

- 拓扑：`sequence` 或 `branching-path`；停靠与绕路必须改变后续距离、天气或理解。
- 默认渲染：`dom` / `canvas-enhanced`；地形高度确有叙事意义时才用 Three.js。
- 适配天气：风、雨、雾、尘、雪、热浪；天气应随路线和停靠改变。
- 推荐阅读工具：`stage-navigation`、`ambience-control`、`notes`、`timer` 中选择 2-4 项。
- Companion 变形：路线在停靠处折成旅行日志、车票背面或休息页。

## 前端实现模式

本节提供该模板的“高质量前端实现语法”指引，用于指导 Coding Agent 产出具备物理感、空间感和极佳交互反馈的 Web 原型。

### 1. 结构与 DOM 层级
这必须是一个具有流逝感和方向性的结构：
- **`z-index: 1` Route Canvas (底图与折痕)**: `concept-image.png` 作为底垫。如果是地图，必须用 CSS 多重背景 (`linear-gradient`) 叠加上折痕的高光与阴影。
- **`z-index: 2` The Path (路径本身)**: 利用极简的 SVG 线条贯穿屏幕（如虚线、曲线）。不要用死板的 `div` 边框代替。
- **`z-index: 3` Waypoints (沿途节点)**: DOM 构建的停靠站（如别针、票根、发光圆点），散落在路径上。
- **`z-index: 4` Environment (环境光与天气)**: 根据站点不同，通过一个全屏的带颜色滤镜的 `div` 切换当地的昼夜、天气。

### 2. 交互与动效技法
- **动态绘制路线 (SVG Path Animation)**: 随着读者推进，路线不应是静态的。
  使用 `stroke-dasharray` 和 `stroke-dashoffset` 配合 CSS `transition`，让线条如同笔迹一样缓缓画出走向下一站的路。
- **纸张/票根物理感**: 站点详情如果用票据呈现，必须有悬浮动画和材质感。
  `box-shadow: 2px 5px 10px rgba(0,0,0,0.15); transform: rotate(-2deg);` 配合 hover 时的微微抬起。
- **视差流动 (如果设定在车厢内)**: 若采用车窗隐喻，窗外背景的 `background-position` 可以通过极其缓慢的动画移动，营造“车一直在开”的错觉。

### 3. 条件式 Three.js 三维路线

`route` 默认使用 DOM / SVG 路线。只有高度、距离、地形或视角变化本身参与叙事时，才选择 `three-diegetic`。

- 适合的三维动作：在桌面沙盘上移动路线标记、沿河流停靠、翻动地形层、改变观察高度。
- 3D 路线必须保持方向清晰，并让停靠动作直接显露旅行日志、天气或时间变化。
- 站点文字、日志、车票和路线选择继续使用 DOM；键盘用户应能按顺序访问全部停靠点。
- 移动端应降级为清晰的二维路线或顺序站点，不保留难以操作的自由镜头。
- 若路线主要承载节点关系与文本，优先使用 SVG path animation。
- 禁止自由驾驶、沙盒漫游和真实地图式导航。

### 4. 各模式实现规范
- **Entry & Exploration**:
  - Entry 时，路线尚未展开。
  - 用户像是在规划旅途，点击“发车”或点击“下一站”的标记。屏幕的环境光应发生变化，暗示时间流逝。
- **Companion Mode (阅读陪伴模式)**:
  - **绝不**在“车窗外”悬浮大段文字。
  - 此时的视点应移回“车厢内”或“路边旅馆”。文字排版必须呈现为放在膝盖上的“旅行日志 (Travel Log)”或是一张被揉皱的车票背面。

### 5. 绝对禁忌
- ❌ **现代地图 API**：绝对禁止直接嵌入 Google Maps、Mapbox 等真实的 Geodata 地图插件。这是意象化的心理旅途，不是外卖跑腿路线。
- ❌ **通用卡片列表**：禁止把每个“站点”都做成那种带个缩略图的通用等宽 Card 组件。它们应当是各种尺寸不一的纸片、邮戳或地理标记。
- ❌ **杂乱的路线**：路线必须清晰，禁止做成让用户到处乱飞乱找的沙盒游戏。
