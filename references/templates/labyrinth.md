# 文本迷宫 (Text Labyrinth)

## 模板标识 (Identity)

当书籍需要通过晦涩的语言、实验性结构、哲学思辨、梦境逻辑、悬疑、递归，或是寻找隐藏在文本转角处的线索来进入时，使用 `labyrinth` 模板。

## 概念图作用 (Image Role)

`concept-image.png` 通常应仅作为**纹理来源 (Texture Source)**和空间暗示，而不是完整的背景图。例如：纸张墙壁、走廊阴影、建筑碎片、没有可读文本的排版纹理、或抽象平面图。

为前端生成该图像时：生成低细节的表面，以便能够被裁剪成面板或遮罩。前端将主要使用 DOM 文本自身来构建路径，因此图像中绝对不能包含原本可读的字迹。

## 美术指导偏好 (Art Direction Bias)

文本建筑学、瑞士编辑排版、纸张迷宫、粗野主义平面设计、墨水走廊、狭窄通道、不含可读单词的排版转折。

## 世界动词 (World Verb)

行走 (walk) / 转向 (turn) / 重读 (reread) / 发现 (find)

## 推进机制 (Progression Mechanic)

读者顺着短小文本走廊转向、回看与重读。走过的路径必须改变后来可见的文本；它不是由若干可点击关键词组成的线性内容菜单。

优秀的节奏示例：
```text
单一的走廊 -> 转角标记 -> 侧房 -> 线性的安全通道
门牌号 -> 旋转的短句 -> 隐藏的台词 -> 阅读线索
```

## 协议映射 (Protocol Mapping)

- `entry`: 可以是一句走廊般的长句、一个门牌号、楼梯标签，或狭窄的通道。
- `exploration`: 应该包含选择转向、揭示简短台词、原路返回，或对齐文本碎片。
- `companion`: 是一条线性的安全通道：一条干净的摘录线索、边缘的地图，或收集到的线索条。

## 交互物件与控件 (Objects And Controls)

使用 2-5 个锚点物件：门牌号、转角标记、楼梯线、边缘箭头、侧房、隐藏短句、引导线。

舞台控制项可以是门、楼层号、走廊刻度、绳结或摘录的步数。

## 路径语法 (Path Grammar)

- 至少存在一次真正分岔；选择一条路径后，另一条路径不是消失，而是在回看时以残句、脚注或不同入口返回。
- 重读是核心动作：同一句话第二次经过时必须因已走路径而改变位置、强调、缺词或邻接文本。
- 路径历史应可见，例如边缘线、折痕、脚印式字距或已收集的转角标记。
- Companion 不是迷宫后的通用阅读面板，而是用户走出的路径被拉直成一条清晰摘录道；路径历史自然成为章节与边注。
- 禁止“点击三个关键词分别展开三段文字”的伪迷宫。

## Frontend Pattern Notes (前端实现模式)

本节提供该模板的“高质量前端实现语法”指引，用于指导 Coding Agent 产出具备物理感、空间感和极佳交互反馈的 Web 原型。

### 1. 结构与 DOM 层级 (Z-Index Architecture)
抛弃传统的上下滚动流，利用网格与排版建立空间迷宫：
- **`z-index: 1` Texture Mask (背景纹理)**: `concept-image.png` 被作为极低透明度的墙壁纹理铺在背景中。
- **`z-index: 2` Typographic Walls (文本墙壁层)**: 核心层。大字号、粗细不一的排版构成了迷宫的墙壁。使用 CSS Grid (`grid-template-areas`) 将文字排成不规则的块和狭长的通道。
- **`z-index: 3` Pathways & Interactions (路径与机关)**: 可点击的转向箭头、高亮的关键词、处于 `height: 0` 隐藏状态的折叠短句。

### 2. 交互与动效技法 (Interaction Recipes)
- **空间排版错位**: 极少数元素可使用 `writing-mode: vertical-rl;` 或 `transform: rotate(-90deg)`，制造转角感。但**切忌**滥用，导致扭曲脖子也看不清。
- **抽丝剥茧的展开 (Accordion Reveal)**: 点击线索后，不跳转页面，而是使用流畅的 CSS Transition（通过动态调整 Grid 间距或 `max-height`）将周围的文本“推开”，显现出里面的核心台词。
- **视差与纵深**: 配合鼠标移动，给后方的文本轻微的负向 `translate`，前方的文本正向移动，造成“在狭窄走廊里行走”的轻微幽闭视差错觉。

### 3. 渲染模式约束 (Rendering Constraint)

`labyrinth` 必须优先选择 `dom`，必要时使用 `canvas-enhanced` 制造局部纹理或轻微景深。文本本身就是墙壁、道路和转角，因此必须保留在可选择、可聚焦、可朗读的 DOM 中。

- 只有空间方向本身不可由排版表达、且 WebGL 仍不承载正文时，才允许极克制的 `three-diegetic` 辅助层。
- 所有路径选择、隐藏短句、回看与 Companion 安全通道必须在禁用 WebGL 后完整可用。
- 禁止把文字做成 WebGL 纹理、让用户用 WASD 漫游、制造眩晕镜头，或以 3D 空间替代清晰阅读。

### 4. 各模式实现规范 (Mode Implementation)
- **Entry & Exploration**:
  - Entry 应该像是一个极其局促的入口（例如屏幕上只有窄窄的一列字）。
  - 用户被迫在文字间“寻路”，点击某些关键词（作为交叉路口），引发周围文本的重新排列和塌陷。
- **Companion Mode (阅读陪伴模式)**:
  - 经历了晦涩的迷宫后，陪伴模式必须是**绝对清晰的避风港 (Safe Passage)**。
  - **绝不**在此时继续刁难读者。排版应恢复为极其干净、优雅的单列长文或手风琴式折叠卡片，让阅读体验畅通无阻，仿佛走出了迷宫来到了宽阔的广场。

### 5. 绝对禁忌 (Anti-Patterns)
- ❌ **做成真正的 3D 游戏**：绝对禁止使用 Three.js 做一个需要用 WASD 走路的第一人称射击/解密迷宫。这是“文本排版的迷宫”，不是游戏。
- ❌ **反人类的阅读体验**：禁止使用让文字彻底颠倒、反转、或字号小到看不清的花招。不管结构多奇特，文本本身必须清晰易读。
- ❌ **复杂的解密锁**：不要设置需要输入密码才能看书的硬核关卡。
